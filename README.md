# TabGroup Auto

智能标签组管理助手 — 自动将新标签页归类到指定标签组，让浏览更有条理。

---

## 功能介绍

自动将新打开的标签页加入指定标签组，并支持按 URL 规则批量归类与排序，方便管理和查找标签页。

### 主要特性

- **默认标签组**：新开标签页自动加入所选标签组
- **独立窗口识别**：可选「不将独立窗口的标签页加入标签组」（如划词翻译等小窗口）
- **URL 规则**：按 URL 匹配（如 `*github.com*`），将匹配的标签页归入指定标签组，支持「应用规则到所有标签页」与「强制移动已分组标签页」
- **标签组与排序**：在弹窗中创建新标签组、一键排序所有标签页
- **FNS 同步（手动）**：配置与各设备的收藏栏快照存入同一个 Vault，本机加密后上传；支持子文件夹和按层级合并收藏
- **兼容 Cloudflare**：保留旧版 Worker 的分组标签页和配置同步入口
- **本地运行**：未开启公网同步时，配置存储在浏览器本地，不收集、不上传任何用户数据

## 安装与使用

### 安装方式

1. 克隆或下载本仓库
2. 打开 Chrome 或 Edge：`chrome://extensions`（Edge 为 `edge://extensions`）
3. 开启「开发者模式」，点击「加载已解压的扩展程序」
4. 选择本项目的根目录

### 基本使用

1. 安装后点击工具栏中的扩展图标打开弹窗
2. **选择默认标签组**：在「选择默认标签组」中勾选要使用的组
3. **独立窗口**：若需排除划词翻译等独立小窗口，勾选「不将独立窗口的标签页加入标签组」
4. 点击「保存设置」生效

### 进阶配置

- **URL 规则**：在弹窗的「URL规则配置」中填写匹配串（如 `*github.com*`）、选择目标标签组，可添加多条规则，并随时「应用规则到所有标签页」
- **标签页排序**：在弹窗中点击「一键排序所有标签页」即可按当前规则整理顺序
- **选项页**：通过扩展右键菜单进入「选项」可进行更完整的配置（与弹窗中的设置一致）

### Fast Note Sync Service 同步（手动）

复用已有的 [fast-note-sync-service](https://github.com/haierkeys/fast-note-sync-service) 服务，无需修改服务端。部署版本需支持 `GET/POST /api/note` 和 `GET /api/notes`。

1. 在 FNS 创建一个 Vault（例如 `browser-sync`），也可以使用现有 Obsidian Vault。
2. 创建可访问该 Vault 的 API Token，授权 REST 笔记读写。若限制客户端，允许 `tabgroup-auto`。
3. 在扩展选项页选择 **Fast Note Sync Service**，填写 HTTPS 服务地址（可带 `/api`）、Token、Vault 名称、本机名称和同步口令。
4. 各浏览器填写相同的服务、Vault 和口令，使用不同本机名称；设备 ID 由扩展自动生成。
5. 弹窗点击「上传本机收藏栏」；另一端点击「刷新云端设备」，选择来源设备后「拉取并合并到本机收藏栏」。
6. 使用「上传扩展配置 / 拉取并应用配置」共享 URL 规则、默认组名和排序设置。

同一 Vault 中的数据布局：

```text
TabGroup Auto/
  config.md                    # 共享配置（最后一次手动上传生效）
  bookmarks/<device-id>.md      # 每个浏览器配置独立的收藏栏最新快照
```

笔记内容为加密 JSON，`.md` 后缀便于 FNS 作为笔记存储；请勿在 Obsidian 中手动修改这些笔记。Token、同步口令、服务地址和设备身份不进入云端配置；本地导出文件也不包含 Token 或口令。设备 ID 与笔记路径可被服务端看到，设备名称、收藏标题、文件夹结构及 URL 存在加密内容中。

**同步范围和合并行为**：

- 仅同步收藏栏（书签栏）及其所有子文件夹中的 HTTP(S) 收藏，保留文件夹层级、空文件夹、收藏标题和重复收藏。
- 不包含“其他收藏夹”、移动设备收藏、受浏览器策略管理的节点或非 HTTP(S) 收藏；不采集正在打开的标签页。
- 拉取时，按同一父文件夹中的文件夹名称、收藏标题和 URL 匹配并复用节点；未匹配的节点按源顺序追加。本地已有内容、标题和顺序保留，不执行删除或覆盖。
- 重复拉取同一快照不会重复添加已匹配的收藏。源数据中的同名文件夹和重复收藏按出现次数分别处理。
- 合并部分失败时会显示已创建的数量；重新拉取可以继续合并，不必删除已添加内容。
- 本版为手动上传与拉取合并。若要让两端内容汇合，A 上传 → B 拉取合并并上传 → A 拉取合并；删除、改名、排序不会自动传播。
- 配置共用一份，后上传覆盖先上传；各设备收藏栏快照分别保存，不互相覆盖。配置中的标签组按名称匹配，避免跨设备使用本地 ID。

**升级与权限**：在 `edge://extensions` 重新加载后，允许新增的“书签”权限。原 FNS 地址、Token、Vault 和同步口令继续使用；配置笔记路径不变。此前试用版本上传的标签页快照不会被删除，但不会出现在收藏栏来源列表中，请重新上传收藏栏。

**从 Cloudflare 迁移**：旧安装默认保留原后端。先拉回原扩展配置，再在选项页切换至 FNS、填写连接信息并保存，分别上传配置和收藏栏。旧 Worker 的云端数据不会被删除。

旧版 Cloudflare 仍使用 `cloudflare-worker.js` 和 KV 绑定 `TABGROUP_AUTO_SYNC_KV`；仅支持分组标签页，恢复到当前窗口。

两种后端均使用 PBKDF2 + AES-GCM、本机随机 salt 加密，建议使用 16 位以上强口令；忘记口令无法恢复密文。FNS Token 作为请求认证凭据发送给配置的服务，仅保存在本机，不作为同步内容。

### 开发验证

无需构建或安装依赖。新增同步逻辑的模拟 API 回归可用 Node.js 运行：

```sh
node --test tests/fns-sync.test.cjs
```

真实验证：在 `edge://extensions` 重新加载扩展并允许书签权限，在两份浏览器配置中连接同一个测试 Vault，上传包含子文件夹、空文件夹和重复收藏的收藏栏。另一端拉取合并两次，确认不重复添加、本地已有内容及“其他收藏夹”不变，配置同步不覆盖连接凭据。

## 隐私说明

默认情况下，本扩展不收集、不上传任何用户数据，所有设置均保存在本机的浏览器存储中。

手动同步时，扩展把所选配置或收藏栏快照加密后上传到配置的 FNS；旧版 Worker 继续支持分组标签页同步；默认不自动上传。服务端保存密文及路径、访问时间、IP、请求大小等元数据。

更多说明见 [privacy-policy.html](privacy-policy.html)（若已安装扩展，可从扩展详情页进入）。

- **v2.5** (2026-11-25)
  - FNS 同步范围调整为收藏栏及其子文件夹，与扩展配置共用 Vault
  - 新增书签权限；拉取按名称与 URL 合并，保留本地收藏，重复拉取不重复添加
  - 保留 FNS 430 笔记不存在的兼容处理，移除 FNS 打开标签页快照入口

- **v2.4** (2026-11-24)
  - 新增 FNS 后端：配置与各设备标签页快照共用一个 Vault，保留本机加密
  - 新增完整标签页快照、云端设备选择和多窗口恢复，保留未分组/固定页面及重复网址
  - 保留 Cloudflare 迁移入口，新增 Node.js 模拟接口回归

- **v2.3** (2026-02-10)
  - 新增公网同步（手动）：同步所有标签组（仅分组标签），支持跨设备拉取并复原到当前窗口
  - 新增同步扩展配置：可上传/拉取 URL 规则、分组排序配置、默认排序方式等
  - 公网同步默认 Worker 地址为 `https://tab.p-pp.xyz`（可在选项页自定义）
  - 加强同步加密：PBKDF2 派生密钥，并为每次上传生成随机 salt，降低弱口令离线猜解风险
- **v2.2** (2025-01-28)
  - 更新标签分组逻辑，更好地支持独立窗口（如划词翻译等）的识别与排除
  - 增强标签组创建与错误处理：标签组不存在时自动创建并更新标题，失败时记录详细错误信息便于排查
- **v2.1** (2026-01-17)
  - 修复浏览器重启后配置丢失的问题
- **v2.0** (2025-07-15)
  - 修复部分场景下独立窗口识别不准的问题
  - 新增按 URL 规则匹配，将匹配标签页批量移动到指定标签组
